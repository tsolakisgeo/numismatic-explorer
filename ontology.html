Data architecture

Ontology-first, interface-ready.

The Turtle records are authoritative. The website creates a disposable browser index without flattening away Nomisma classes, properties, or controlled-resource URIs.

Physical objects and archival evidence

Every physical coin is represented as nmo:NumismaticObject. Inventory cards remain separate cor:InventoryCard resources connected to the coin. Card-derived readings can support searching, but card transcriptions and card images are intentionally not displayed publicly in this version.

Controlled values and fallback literals

URI-backed Nomisma values are always preferred. Where an older or card-derived TTL record contains only a raw literal, the build may expose that literal as a clearly distinguished fallback filter value. It does not invent a Nomisma identifier or claim equivalence without evidence.

Photograph mapping

data/coin_photos.csv is a lightweight many-to-one mapping. Repeating a coin identifier creates multiple METIS photograph-resource links. The two-column tab-separated format is sufficient; optional columns can later provide side labels or direct image URLs.

Static publication

GitHub Actions parses and validates Turtle, builds coins.json, facets.json, and schema.json, then publishes the static interface. The generated JSON is an index only and can always be recreated from the RDF and CSV sources.
